# Rival Saga Implementation Status

## Battle Phase / Teambuilder Integration

The Battle Phase page no longer acts as a second team editor. Teambuilder now presents the submit/lock action and writes revisioned exact-instance snapshots containing Badge assignments, selected Battle Species, legality data, and frozen set information. Battle Phase renders read-only trainer summaries, sanitized mystery/revealed team strips, a six-step phase rail, and viewer-safe matchup strips while preserving revision windows, battle reporting, schedules, records, standings, payouts, and history.

Durable reveal grants support player, selected-player, opponent, public, and host scopes at four explicit reveal levels. Team Preview grants public summary knowledge and exact-instance grants survive refresh and unrelated slot revisions. Hidden Battle Phase markup omits species, sprites, sets, and roster IDs. Full backend payload scoping is not yet implemented, so private full-set reveal effects remain blocked rather than relying on client-side hiding. The focused Battle Phase contract suite contains 6 passing checks.

## Site Shell Game Loading

The outer shell now lists authoritative saves through a shared, tolerant game-summary contract and the same runtime API origin used by the inner game. Large saves are scanned with bounded memory and cached by file metadata. Current, legacy, Token/Live Referee-rich, and optionally malformed records remain listable; unsupported schema versions are reported without replacement or migration. The default unprofiled view shows all authoritative games instead of an empty “My Games” result.

Stale game/profile/trainer references are handled independently. Missing game deep links return to the populated library and no longer auto-create blank records. Read-only listing/opening no longer rewrites state or token-art assets. Development diagnostics expose origin, request state, authoritative/normalized/excluded counts, selected identities, rejected IDs/reasons, and schema versions. Known isolated `codex-*` and `browser-smoke` records are excluded from the normal list.

The focused shell suite contains 11 passing unit/integration/static scenarios. Browser validation on port 4175 covered list hydration, exact-ID open, refresh, return/reopen, back/forward, stale-game recovery, backend failure, retry, restart/reconnect, matching Gym/phase, and a clean warning/error console on the repaired bundle. File hashes confirmed zero authoritative game-record changes during list and restart checks.

## Token Scenario Sandbox

The sandbox uses an in-memory working state, private entry baseline, session ID, and authoritative entry revision. Low-level local and backend gameplay writes fail closed while active. Multiplayer events are paused or buffered. Discard reloads authoritative state; revision-aware reconnect catches up if the server advances during exit. Commit uses optimistic concurrency, strips testing/client-only state, preserves suppressed preexisting events, and supports idempotent recovery by session ID.

The sandbox suite currently contains 18 passing infrastructure tests. Validation performed before commit is **structural validation**: object shape, player presence, required major arrays, and JSON serialization. It is not complete Rival Saga legality or state-integrity validation.

Advanced Repair remains experimental. Its snapshot and chronology model is not complete enough for complex live repair.

## Live Referee

Ordered response priority, per-prompt pass/response state, child prompts, parent pause/resume, and targeted-player priority are partially functional. Compatibility metadata such as `canRespondTo` is not fully enforced, effect legality is incomplete, and many resolutions still require Guided or host work.

Live Referee situations now persist an explicit lifecycle separate from legacy Activity status: `pending`, `awaitingResponse`, `awaitingRequiredChoice`, `resolving`, `resolved`, `canceledRefunded`, or `failedRecoveryRequired`. Active records identify the acting player, required action, progression block, resume point, Token-consumption state, and mutation progress. Terminal lifecycle records do not reopen after reload, completed mutations reconcile stale open shells without replay, and interrupted/unsafe resolutions enter host recovery instead of remaining an unexplained open event. The host-only `Cancel Event And Refund` path is available only for recovery-required records and restores the declaration snapshot before one idempotent refund when partial mutation began.

The backend response route now requires `/activity/:id/responses` and cannot fall through to generic Activity creation. Response-shaped records are rejected as standalone situations by both persistence and client normalization. The focused lifecycle suite contains 10 passing scenarios covering the historical misrouting shape, refresh, required choices, stale completed shells, partial rollback, duplicate completion, terminal reload, collapse/reopen, navigation release, and backend nesting.

The floating Live Referee now has a persistent gameplay HUD around Situation + Choices: Series/Gym and canonical phase context, current actor or priority owner, public context chips, compact prompt trail, five stable player positions, contextual player states, a hierarchical Gym/Battle rail, expanded result presentation, a useful collapsed table summary, responsive compact/minimum layouts, keyboard-visible native controls, and reduced-motion fallbacks. Team Lock and Action status are derived from their existing authoritative records; response state uses the current prompt's frozen priority record; battle reporting status is shown when a current schedule exists.

The HUD now supports floating, right/left/bottom docked, expanded, full-table, and collapsed presentations using device-local preferences. Floating bounds reach 96% of the practical viewport; automatic surface-aware allocation, Situation/Table focus, and a persisted pointer/keyboard divider replace the rigid split. Collection and reading screens retain bounded content scrolling with reserved command bars, and compact pentagon mode keeps all five stable seats plus actor, priority, controlled, waiting, confirmation, and alert states. Appearance controls expose density, 90/100/110% scale, and reduced motion without rerendering the surrounding Game Manager or resetting form drafts. Existing single-player target options are mirrored onto the matching pentagon nodes and route back through the existing select/change path; the form remains the fallback and no target legality is added. Lightweight announcements are derived only from existing Action-complete, Team-lock, revision, priority-complete, and effect-result records.

Action visits now create a persisted, idempotent Action operation. Visit confirmation spends the Action once, while the operation keeps the same player and Action number current until its linked location session and chronology blockers finish. Hidden Grotto, Encounter, Silph Co, Bulletin Board, wheel services, Dragon's Den, Ranger Base, Field Token, Daycare, Game Corner, Pokemon Center, Graveyard, and PC are wired to the shared contract. Multi-service locations require the visible Finish Action control. Generic immediate services complete through the shared path. Interaction resolution retries a completion that was waiting on a linked response chain.

The effect/Token picker now keeps its title and Back/Cancel navigation outside a bounded internal card scroller. Browser verification covered 37 effects at the desktop overlay and a 520px viewport; the header and footer remained non-overlapping and visible, the collection overflowed internally, and the final effect remained selectable. The focused Action-operation contract suite contains 12 passing lifecycle and wiring tests. These tests cover the operation/turn protocol and static integration points; they are not proof that every location-specific gameplay effect is otherwise complete.

Live Referee controlled-player context now separates Site Shell viewer identity, viewer-linked trainer, current decision owner, and gameplay-controlled trainer. Normal multiplayer remains profile-bound and shows a waiting screen rather than another trainer's effect resources. Free Testing automatically follows response priority, pending Trade acceptance, unfinished Action operations, required manual tasks, and Team Build/Lock decisions. Effect inventory, drafts, consumption, event actors, response logs, Trade forms, and the pentagon badge share the same helper; stale navigation is invalidated when the decision owner changes. The focused context suite contains 12 passing scenarios. Browser revalidation of this change is still pending because the current in-app browser session rejected access to the local development address.

Effect presentation reads actor, target, Token art, prompt ancestry, result announcements, and lingering public statuses from existing state. New in-session prompts can play a short actor-to-target announcement; reload does not replay it. Missing art falls back to a readable badge. This layer is decorative and does not participate in effect resolution.

The phase-boundary offer queue, semantic Control-open query, complete effect legality filtering, redirection, and several battle-payout/reporting details remain incomplete. The HUD only displays those states when an authoritative runtime record already exists; it does not infer or create missing procedures.

The Live Referee Token surface now routes through `getUsableEffectsForContext`. Canonical inventory identity, quantity, runtime usability, declaration-versus-reaction mode, exact timing permission, current targets, and blocking Battle revision operations are checked together. Sabotage visibility is contract-driven through `timingPermissions.sabotageCurseWindow`; unrelated Control, Field, Protection, and Encounter effects do not inherit the Curse window.

Successfully resolved standard Curses that change locked-set legality now create a persisted `WAITING_FOR_REVISIONS` parent operation with exact-instance child tasks. Sabotage, proactive declarations, and Team Preview remain paused until every task passes full-team legality, respects its allowed edit scope, and is explicitly reconfirmed through Teambuilder. The locked snapshot and revision number update only on confirmation. Removed source statuses cancel obsolete tasks from current authoritative state without restoring an old snapshot. This operation flow is implemented for the currently automated standard Curse resolver; future class, perk, and multi-target effects must return equivalent revision requirements before they can use it.

Substitute now has a focused automatic foundation: owned-instance placement, duplicate prevention, interception after response negation and before parent mutation, exact-instance exclusions, persistent species-wide exemptions, and the species-Ban exception. Standard Pokemon-name Curses select one exact Active Roster anchor, then apply to every matching Active Roster instance across players; Arena Curse immunity and Substitute exclude matching instances independently while other matches continue. Extra Ban remains the selected-anchor exception: it checks Substitute only on that anchor, and one selected Substitute negates the universal Ban without touching another matching attachment. Live Referee records affected, protected, and excluded exact instances.

## Known Dangerous Or Deferred Systems

- Incorrect or incomplete effect-specific timing remains possible despite corrected family defaults.
- Token-consumption outcomes after illegality, cancellation, negation, blocking, no effect, or host rejection need a final lifecycle ruling.
- Sticky Hold is mechanically enforced for the verified Pokemon-targeting Steal Token. Safeguard and future money, Item, TM, and Token theft/destruction/copy operations still require their own category-specific enforcement.
- Authenticated Foresight delivery remains incomplete and blocked; recursive shared-payload sanitization removes all private records. After You's custom-choice Control and unsupported Protection interactions fail closed individually. Follow Me still needs effect-specific Gym-end expiration and History-undo browser evidence. Teleport intentionally supports only exact root Token events handled by the Control controller. Purge's post-payout path is wired but still lacks destructive browser evidence; Revenge still needs one complete payout-to-offer phase-through smoke test.
- Field placement state exists, but ongoing Field mechanics are largely absent.
- Guided resolvers commonly record text without applying the complete effect.
- Future class/perk effects and nonstandard multi-target Curses are not yet wired to the blocking Sabotage revision operation, even though the parent/child model supports them.
- Substitute's final consumption/refund lifecycle and exact Gym-duration boundary remain unresolved rules questions.
- Rage Candy Bar and Restrict now enforce instance-scoped immunity in the structured path. Rage Candy Bar uses one shared timed enhancement and repeated uses extend rather than stack it, but its exact Gym-duration boundary is still provisional.
- New Tricks is not implemented. The shared model can represent submitted-team instance restrictions without converting them into species-wide Restrict.
- Arena Trap is `verifiedComplete`. It creates one linked exact-instance record, validates that rival Active-roster target through authoritative Teambuilder bring legality, immediately inserts and locks it in the current Battle Phase draft/team, preserves any minimum Badge assignment, blocks Curse declarations, and creates mandatory repair instead of deleting a member when a team is full. Target eligibility is independent from compensation: targets at least two ordered Battle Tier steps below the Natural tier require their owner to choose one AAA-approved Ability or injectable move before Team Lock. The exact structured grant appears in the generated set, persists through reload, expires and undoes with Arena Trap, and uses the shared customization-ban registry with explicit Trainer Class overrides. Stale confirmed declarations cancel and refund before mutation. Unit, Integration, Result, Browser, reload, undo, expiration, and idempotent sandbox evidence cover the approved lifecycle.
- Incinerate is `verifiedComplete`. It independently selects one exact non-Master-Ball Item or TM record from every rival who has a legal target, atomically destroys those stable-ID records, skips rivals with no legal target, never affects the source player's sheet, and resolves an entirely empty selection with no effect. Immunity negation, atomic failure, exact result summaries, reload, duplicate-completion protection, undo, browser refresh, and sandbox discard/idempotent commit are covered.
- Steal is `verifiedComplete` for its approved Pokemon roster-instance effect. It transfers one exact rival Pokemon to the source player's Active roster, removes stale current Battle Team and active Teambuilder references from the prior owner, records exact previous/new ownership, obeys Sticky Hold, is not blocked by Safeguard's money/Token wording, and is intercepted by Substitute. Reload, undo, stale-target refund, result summaries, browser refresh, and sandbox discard/idempotent commit are covered.

The copy retains its definition/timing/targets, survives refresh, and is removed unused at the next Gym boundary. Counterspell is also `verifiedComplete`: it can answer only a response that would negate the user's own exact Token activation, restores that consumed inventory ID as the explicit consumption exception, and keeps it visible but unusable until the same phase two Gyms later. Reserve, Released, Daycare/facility, Temporary, and other non-Active-roster records are ineligible even if a stale team reference exists. Live Referee now awaits the same lazily loaded authoritative Pokemon/evolution dataset used by the resolver and automatically replaces its loading state with legal exact-instance targets. Resolution preserves the stable roster-instance identity, applies normal acquisition-stage and Series Evolution Lock rules, resets species-specific set fields, and atomically updates the Active Roster plus any existing current-team, locked-slot, or Teambuilder references to that exact ID without creating team membership.
